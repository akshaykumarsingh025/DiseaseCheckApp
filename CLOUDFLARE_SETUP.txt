---------------------------------------------------------------------------
 PART 1 - THE 3 SECRET KEYS YOU MUST SET
---------------------------------------------------------------------------

These are SECRET. They are stored by Cloudflare, never in git, never in the
app. You set each one with a command and paste the value when prompted.

  1. LIVEKIT_API_KEY
       What:  LiveKit API key (starts with "API")
       Where: https://cloud.livekit.io -> your project -> Settings -> Keys
       Note:  This is the SAME key/secret pair currently in Google Secret
              Manager for the old Cloud Function.

  2. LIVEKIT_API_SECRET
       What:  LiveKit API secret (long random string)
       Where: Same page as above - shown when you create/reveal the key

  3. GROQ_API_KEY
       What:  Groq API key (starts with "gsk_")
       Where: https://console.groq.com/keys
       Note:  This is the key currently sitting in Firestore at
              config/api_keys -> groq_api_key


 There is no 4th secret. Moderator control is handled by DOCTOR_EMAILS,
 which is already set in worker/wrangler.toml - see PART 6.


---------------------------------------------------------------------------
 PART 2 - COMMANDS TO RUN
---------------------------------------------------------------------------

Open a terminal in the project and run these in order:

    cd worker
    npm install
    npx wrangler login              <- opens browser, sign in to Cloudflare

    npx wrangler secret put LIVEKIT_API_KEY
    npx wrangler secret put LIVEKIT_API_SECRET
    npx wrangler secret put GROQ_API_KEY

    npx wrangler deploy

Each "secret put" will prompt:  "Enter a secret value:"
Paste the value and press Enter. Nothing is echoed to the screen - that is
normal.


---------------------------------------------------------------------------
 PART 3 - COPY THE URL INTO THE APP
---------------------------------------------------------------------------

"wrangler deploy" prints a URL like:

    https://diseasecheck-api.YOUR-SUBDOMAIN.workers.dev

Put that URL in ONE of these two places:

  Option A (in code - needs an app rebuild):
      File: lib/config/backend_config.dart
      Change _defaultBaseUrl to your real URL.

  Option B (in Firestore - no rebuild needed, and overrides Option A):
      Collection: config    Document: api_keys
      Add field:  backend_base_url  (string)  = your real URL

Option B is handy later if the URL ever changes.


---------------------------------------------------------------------------
 PART 4 - VERIFY IT WORKS
---------------------------------------------------------------------------

Run this (replace with your URL):

    curl https://diseasecheck-api.YOUR-SUBDOMAIN.workers.dev/health

Expected output - ALL FOUR must be true:

    {"ok":true,"livekit":true,"groq":true,"project":true}

    livekit:false  -> LIVEKIT_API_KEY or LIVEKIT_API_SECRET not set
    groq:false     -> GROQ_API_KEY not set
    project:false  -> FIREBASE_PROJECT_ID missing from wrangler.toml

/health never reveals any key value, only whether it is present.

---------------------------------------------------------------------------
 PART 6 - MODERATOR CONTROL (DONE - already configured)
---------------------------------------------------------------------------

"roomAdmin" controls who can kick people out of a call and end it.

The old Cloud Function decided this from an isModerator flag SENT BY THE
APP, so any signed-in user could simply claim to be the doctor.

FIXED. worker/wrangler.toml now sets:

    DOCTOR_EMAILS = "drdipikasingh2026@gmail.com"

The Worker grants roomAdmin only when the Firebase ID token carries that
email AND email_verified is true. The app's isModerator flag is ignored.
No Firebase UID lookup is needed - this matches how the app itself
identifies the doctor (DoctorAccountService.isDoctorEmail).

If the doctor's address ever changes, edit that line and redeploy.
(DOCTOR_UIDS is also supported if you ever prefer pinning exact UIDs.)


 !! STILL OPEN - THE DOCTOR PASSWORD IS PUBLIC !!

 lib/services/doctor_account_service.dart hardcodes BOTH the doctor email
 and password, and that file is committed to a public GitHub repo. Anyone
 who reads it can log in as the doctor - which defeats DOCTOR_EMAILS,
 because they would then genuinely BE the doctor account.

 To actually close this: change the doctor account's password in Firebase
 Console -> Authentication, and stop hardcoding it in the app. The app only
 needs the password because it auto-creates the doctor account on startup;
 that account already exists now, so the create-on-startup path (and the
 password constant) can be removed.


---------------------------------------------------------------------------
 PART 7 - NON-SECRET SETTINGS (already filled in, edit if needed)
---------------------------------------------------------------------------

These live in worker/wrangler.toml in plain text - they are not secrets:

    FIREBASE_PROJECT_ID   = diseasecheck-57cc2
    GROQ_BASE_URL         = https://api.groq.com/openai/v1
    GROQ_ALLOWED_MODELS   = which Groq models the app may request
    GROQ_MAX_TOKENS       = 8192  (hard cap on response length)
    ALLOWED_ORIGINS       = CORS list, only matters for a Flutter WEB build

Rate limits are also configured there: 20 AI calls/min and 10 call-token
requests/min, PER USER, so one account cannot burn your whole Groq quota.
